# 生物地球仪数据源调研:海洋 / 淡水 / 真菌 / 昆虫 / 微生物

> 调研对象:面向 globe.gl / three-globe 3D 地球可视化(「文明史交互网络图」姊妹项目同一技术栈)的生物地理数据源。
> **进度状态(第二次落盘):6 路并行子调研中,5 路已完成、1 路仍在执行**。已完成:①海洋生物地理分区系统、②淡水、③真菌、④昆虫与无脊椎动物、⑤微生物。进行中(本文对应 1.2 节标记【待补】,完成后会再次更新本文件):海洋生态系统专题分布(珊瑚礁/红树林/海草/海带林/深海分层/洋流上升流)。
> 最后落盘时间:2026-07-31。

## 0. 怎么用这份报告

- 每个数据源给出:官方下载 URL、格式、体积、许可、引用文献、可视化方式(矢量边界 or 点位/栅格需加工)、验证状态。
- **验证状态图例**(严格区分,不含糊):
  - **已验证 URL 可访问** = 调研者本人用 WebFetch 实际打开了该页面/API并读到了真实内容(会在条目里简述看到了什么,比如返回的 JSON 字段、下载按钮跳转到的真实文件名)。
  - **仅搜索结果确认** = 多个独立信源(论文全文、GitHub仓库、第三方教程)对同一事实说法一致,但目标官网本身因反爬/JS渲染/证书问题未能被直接 WebFetch 验证。
  - **仅文献/搜索结果提及** = 只在论文正文或搜索摘要里见到过,没有交叉验证,可信度最低,使用前建议自己再打开一次。
- 表格里的"可视化方式"对应 globe.gl 的图层类型:
  - **矢量边界 → `polygonsData`**:GeoJSON/Shapefile(转GeoJSON后)多边形,可直接画分区/生态区/流域/湖泊轮廓。
  - **矢量线 → `arcsData`**:河流、洋流流线。
  - **点位 → `pointsData` / `heatmapsData` / `hexBinPointsData`**:采样站点、物种出现记录,数量大时需按经纬度格网或 H3 六边形聚合成密度图,不要逐点渲染。
  - **栅格 → 需转 `tilesData` 瓦片或先抽等值线转多边形**:NetCDF/GeoTIFF 连续场(如菌根类型概率图、土壤微生物预测图),不能直接喂给 polygonsData。

## 6. globe.gl 工程实施建议(基于已完成部分先行给出)

1. **矢量边界类(可直接 `polygonsData`)优先级**:HydroLAKES → Longhurst Provinces(走WFS免注册)→ HydroBASINS低层级 → MEOW/PPOW → FEOW → Fish-SPRICH流域。这几个都已验证下载可达、格式明确,建议作为第一批接入的图层,且都需要 shapefile → GeoJSON(ogr2ogr/mapshaper)+ 简化(douglas-peucker减面,参考本项目`tools/build_borders.js`已有的疆界简化管线可直接复用同一套工具链)。
2. **点位聚合类(`pointsData`/`heatmapsData`/`hexBinPointsData`)**:OBIS(海洋物种出现记录,按类群批量拉取+H3聚合)、GlobalFungi(真菌采样点)、GBIF地衣记录,三者都是"记录数百万级、坐标点级"的数据,**绝不能逐点渲染**,统一走"先按1°网格或H3聚合成密度值,再喂 hexBinPointsData"的管线,可以写一个通用的"occurrence records → grid density → globe.gl layer"预处理脚本复用于这三类数据以及后续昆虫/微生物点位数据。
3. **栅格类(需转 `tilesData` 或抽等值线)**:Steidinger 2019 菌根类型1°网格图是目前唯一确认的栅格数据,分辨率较粗,建议直接做"网格色块"当作粗颗粒度的 `polygonsData`(每个1°×1°网格就是一个小方块多边形,反而比转瓦片更简单),不必上瓦片管线。
4. **许可红线**:HydroLAKES/HydroBASINS/HydroRIVERS/HydroATLAS/Fish-SPRICH/Free-Flowing Rivers/GlobalFungi/GBIF(CC0部分)是目前许可最清晰的一批(CC BY 4.0或更宽松),**如果项目未来有商业化/加广告变现的可能性,MEOW/PPOW/FEOW/Longhurst 都需要单独核实或取得书面授权**(尤其FEOW明确禁止商业使用)。当前"文明史交互网络图"是免费公开的GitHub Pages静态站,非商业展示应该都在安全范围内,但落地前建议再逐一确认。
5. **复用现有管线**:本项目`tools/build_borders.js`(下载→mapshaper精简→环绕方向修正→合并小邦)的思路可以直接套用到 MEOW/FEOW/HydroBASINS 等生态区边界上;`data/`目录下已有的 GeoJSON 处理经验(比如`land_compact.json`的精简手法)也可以复用。
6. **现成"全球连续多样性栅格"清单**:目前只确认了三个——Steidinger 2019(菌根类型,1°粗网格)、Kass et al. 2022(蚂蚁,CC0,约20km分辨率)、Daru 2024(蝴蝶,约10km分辨率,GeoPackage+GeoTIFF双格式)。这三个可以作为"生物多样性热力层"的骨架优先接入,尤其蚂蚁和蝴蝶两个都是CC0/可重用许可、体积可控(几百MB到几GB)。
7. **稀疏站点直接当点位用**:Tara Oceans(210站点)和 Bahram 2018(189站点)站点数量本来就少,不需要额外聚合/格网化,可以直接当高亮 `pointsData` 展示"海洋/土壤微生物采样远征"这种叙事性图层,和文明史项目"事件点"的展示逻辑相通。
8. **数据空白提醒**:全球昆虫多样性纬度梯度、IPBES传粉者评估、Delgado-Baquerizo土壤细菌图谱三项**目前没有找到可直接下载的现成空间数据**,近期只能退而求其次用GBIF点位数据自建聚合,或暂时借用论文插图作参考底图重绘,不要在首版排期里假设这三项能"即插即用"。

## 7. 已知坑点汇总

- **marineregions.org 不是万能托管方**:它是 Longhurst 的权威源,但 MEOW/PPOW 得去 TNC ArcGIS Hub 或 UNEP-WCMC 拿。
- **同一数据集常有多个镜像、许可口径可能互相打架**(MEOW三个镜像三种许可措辞),不要只看第一个搜到的页面就下结论。
- **figshare/iucnredlist.org/rsis.ramsar.org 对自动化WebFetch有反爬/证书问题**(403/502/证书过期),这类情况已如实标"仅搜索结果确认",人工去开一次确认更稳妥。
- **GlobalFungi、antmaps.org 这类站点是JS单页应用**,WebFetch/无头抓取拿不到真实统计数字,需要人工打开浏览器看,或者找论文/GitHub仓库做旁证。
- **BioFresh/Global Freshwater Biodiversity Atlas 疑似已停止维护**(2014年后无更新痕迹,主站连接失败),不要把它当长期依赖。
- **本次调研会话的 WebSearch 额度已耗尽(200/200)**,导致海洋生态系统专题(1.2节)后半部分完全没能展开搜索——如果后续要补全,需要新开会话或提高`CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`额度。
- **期刊官网(Cell/ScienceDirect/Science.org)对WebFetch几乎全部403**(付费墙+反爬双重拦截),但配套的 Dryad/Zenodo/PANGAEA/ENA 数据仓库通常还能访问——遇到期刊官网403时,应优先找该论文的Dryad/Zenodo/ENA数据页,而不是死磕期刊官网(Daru 2024蝴蝶、Kass 2022蚂蚁两个数据集都是这样从Dryad验证成功的)。
- **GABI/antmaps.org 明确没有批量下载/API**,底层原始数据需邮件联系作者(Evan Economo / Benoit Guénard);如果只是要"全球蚂蚁多样性栅格"这个可视化需求,直接用同团队产出的 Kass et al. 2022 Dryad栅格(CC0,已验证)替代即可,不必等antmaps.org开放下载。
- **私有分享链接(figshare `/s/...`、部分Dryad预发布链接)不稳定**,白蚁iScience 2022论文的数据就挂在这种私有链接下,使用前务必人工重新打开确认仍然有效,不要直接写死进代码管线。
